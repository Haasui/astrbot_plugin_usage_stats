# 架构与统计口径

采集层记录文本模型调用，统计层保留日汇总，可选明细提供更细的查询。页面、价格和设置都通过 AstrBot Bridge 调用装配层接口，不独立代理模型流量。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| [main.py](<../main.py>) | 生命周期、配置、记账装配、聊天指令与 Web 接口 |
| [patch.py](<../patch.py>) | 发现 provider 类方法、包装调用、识别结束状态与还原 |
| [attribute.py](<../attribute.py>) | 从模块调用栈识别插件，提取连接标识与会话信息 |
| [stats.py](<../stats.py>) | 调用数据模型、Token 转换、日桶聚合与文本输出 |
| [store.py](<../store.py>) | JSON 日汇总序列化、合并、裁剪与原子替换 |
| [event_store.py](<../event_store.py>) | SQLite 明细、价格、提交证明和统一查询 |
| [price_catalog.py](<../price_catalog.py>) | 有界获取并解析 Models.dev 公共参考价格 |
| [页面](<../views/usage/index.html>)、[交互](<../views/usage/app.js>)、[算法](<../views/usage/dashboard.js>) | 显示统计、编辑设置和手工价、管理筛选及图表状态 |

纯统计、存储和解析模块不依赖 AstrBot 运行时，宿主依赖集中在装配层。

## 采集与归因

[装配层](<../main.py>)递归发现 Provider 及子类自己定义的 text_chat 和 text_chat_stream，并由包装器采集。它记录经过这些方法的文本调用，不包含其他进程、绕过这些方法的直接 SDK 调用或独立的 embedding、音频、图片生成接口。

包装器按同步、可等待结果和异步生成器处理调用。正常、失败、取消和空正常流均有结束路径；记录故障不应替换原模型结果或原异常。首段时间只从能够证明存在文本或工具内容的片段建立，不把仅含 usage 的片段当作首 Token。

保持以下约束：

- 不修改模型请求或响应内容，不给 provider 实例写统计属性。
- 默认关闭采集，卸载和运行时关闭通过注册表还原所包装的方法。
- 用 ContextVar 与消费任务身份避免嵌套 super 链重复记账，独立任务不相互抑制。
- 记账与保存错误留在统计路径，不向模型调用方抛出。

来源识别使用调用栈中的插件模块名；无法识别时归为 main_agent。provider 优先取实例配置中的连接 ID，模型取 provider.get_model()。这是请求配置模型，不通过响应模型名或价格目录反推别名。

provider 类可能在插件初始化后才加载，因此发现过程使用定时重扫，不依赖“先收到一次调用”。方法计数是内部包装位置的数量，不是模型账户数、请求数或漏洞修复数量。精确标签由运行诊断返回，不根据计数推断有哪些类。

## 统计口径

[查询聚合](<../event_store.py>)先统一过滤，再生成总览、分析、明细与价格统计。

| 指标 | 定义 |
| --- | --- |
| 调用数 | 已记录调用的数量，包含失败与取消，不是供应商 HTTP 尝试次数 |
| Token 总量 | input_other + input_cached + output；无完整用量时不从字符数估算 |
| 成功率 | 成功 /（成功 + 失败），已识别取消不进入分母；分母为零无有效比例 |
| 缓存命中率 | 可用缓存样本的缓存读取 Token / 输入 Token；按 Token 比例，不按命中请求数 |
| 缓存构成占比 | 同一可用缓存样本的缓存读取 Token / 总 Token，分母包含输出 |
| TPS | 成功且有正输出和有效耗时的明细：总输出 Token / 总耗时秒数，不平均每行 TPS |
| 平均耗时 | 有耗时明细的 latency_ms 均值，包含这些样本中的失败与取消 |
| RPM | 已记录调用数 / 查询窗口分钟数；窗口至少一分钟，不是最近一分钟滚动请求量 |
| 估算费用 | 当前有效价表对能够计价的记录求和，同时报告未计价数量 |

input_other 是 AstrBot 的归一化输入列，可能包含缓存写入。原始思考与缓存写入单独作为参考字段，不再加入三列总量。部分字段未上报时，汇总只覆盖可获得的计数，不能据此断言完整真实消耗。

缓存比率只使用明细或完整上报的旧日桶。旧日桶仅部分调用上报缓存时，无法分离准确输入分母，会从比率样本中排除。页面构成图和指标的覆盖含义应与样本说明一起看。

默认 TPS 使用整个调用耗时，包含等待与流消费时间，不是纯模型推理速度。后端支持的 ttft 模式会扣除首段时间，并要求有效生成窗口不少于 100ms；缺少合法首段时间时不补零样本。

## 统一查询与时间

查询的插件、provider 和原始模型名精确匹配。日界固定为 UTC+8，自定义时间使用带时区时间戳和半开区间 [start,end)。候选项只受时间窗口影响，避免选择某个模型后其他选项消失。

旧日桶只能提供日粒度统计，无法精确匹配的结果/子日筛选会排除它。趋势根据范围和旧日桶情况选半小时、小时或天；缺时段补零，长范围合并相邻桶，单次最多366点。图例显隐不改变查询条件。

## 费用计算

有效价格按以下顺序选择：手工 provider/模型精确项、手工通用模型项、公共目录精确模型项。公共目录按模型 ID 消歧，不去日期、不按模型族猜价。已知原厂来源优先，否则只有候选价格一致才保留。

[费用函数](<../event_store.py>)对普通输入、缓存读取、缓存写入和输出分别计价，并除以一百万。可证明的缓存写入从 input_other 中拆出用于价格分项，但不改变 API 的原始输入列。缓存写入超过归一化输入等不一致情况不强行计价。

必需单价缺失时保持未计价；显式零价合法。历史估价按当前价表重新计算，没有在调用时冻结价表版本。Models.dev 目录与手工覆盖使用不同表，同步失败不替换旧目录。

## 日汇总与明细的共同提交

日汇总保留插件、日期和 provider/模型键的计数，结构化明细以稳定 event_id 幂等写入 SQLite。查询不能假定两份数据天然同步。

1. 先尝试写入明细；未写入项可在队列中重试，但队列受明细上限约束，超限会丢弃最旧未写明细并告警。
2. SQLite 准备提交证明，包含当前明细以及本次日汇总已纳入的待写明细 ID。
3. JSON 通过同目录临时文件原子替换，连同 event_checkpoint 一起发布。
4. 成功后更新内存基线、清空对应逐条缓冲，释放旧证明并裁剪明细。
5. 失败时保留原日文件、原证明与待保存的日汇总调用，不按日汇总内存目标丢弃它们；这不解除待写明细队列的上限。

重启时，把 SQLite 中未被最后日汇总证明包含的调用恢复为待保存记录，保留 event_id，不增加本次启动的新调用计数。查询只相减已证明包含的明细，剩余统计作为日粒度历史。

没有包含关系证明的非空旧实验数据库不自动猜测合并，原库保留并降级到日汇总。备份与还原应成对处理文件，步骤见[使用指南](<USAGE.md#备份与重置>)。

## Web 设置与边界

[设置接口](<../main.py>)持有原始 AstrBotConfig 对象，不只修改启动时的字典副本。提交需登录、通过四字段类型/范围验证与设置版本检查；持久化确认后才替换运行配置。配置写入失败与运行状态部分应用是不同回执。

页面经宿主 Bridge 调用 stats（dashboard/export）、prices、price_sync、settings 和 reset。新增统计/导出分支及写接口显式检查 Dashboard 登录；兼容的统计和日志读取形态保留。它们不是模型转发 API，也不以公开无鉴权接口为使用方式。

数据文件内容和隐私边界统一见[使用指南](<USAGE.md#日汇总明细和文本日志>)；配置默认值统一见[配置参考](<CONFIGURATION.md>)。
