# 0.3.1 价格数据与紧凑布局验证

## 修正范围

价格页从统一查询的 pricing.rows 展示实际模型调用数、Token、费用和单价。未配置手工价格时，已用模型仍然可见；缺价使用缺失态，不显示为免费。公共目录与手工覆盖分别存储，删除覆盖后可使用匹配的公共参考价。

页面使用标签与状态同排、五个原生下拉筛选、费用汇总与工具栏同排的结构。大标题和常驻筛选说明不占布局空间。桌面默认顶部的 CSS 高度预算为 116px，价格表行高为 44px；窄屏自然换行。预算来自 [样式](<../../views/usage/style.css>)，尚未通过真实浏览器测量。

## 已执行结果

- Python 回归共 223 项通过，包括原采集/日汇总、数据库升级、崩溃恢复、新价格投影和目录解析。受限执行时两项临时目录 IO 被 Windows 权限阻止；获准后运行同一验证命令，全部通过，未修改系统权限。
- Node 两个源码语法检查、[图表算法测试](<../../tests/dashboard_smoke.mjs>)和[页面冒烟](<../../tests/view_smoke.mjs>)通过。页面测试额外读取真实 HTTP 查询响应，检查价格页费用、已用模型、目录条目和采集状态，避免只验证手工构造的价格行。
- Git diff --check 通过。
- 真实请求 [Models.dev API](<https://models.dev/api.json>)成功，解析得到 3183 个无歧义的可用参考价格。输入/输出价格保持 API 的 USD / 百万 Token 单位，没有再次转换倍率。
- 使用真实查询引擎与模拟调用的 HTTP 预览，从“252 次调用、6 个已用模型/provider组合、无手工价、费用未知”开始。更新公共目录后 252 次调用可计价，手工价表仍为空；全局模型筛选得到 92 次调用，并与价格行合计一致。以上为模拟数据，不是用户真实账单。

## 价格链路验收

| 场景 | 检查 | 预期 |
| --- | --- | --- |
| 有调用但无手工价 | [价格投影测试](<../../tests/test_pricing.py>) | 模型行显示实际调用数和用量，费用为缺失态 |
| 更新公共参考价 | [装配测试](<../../tests/test_integration.py>)、HTTP预览 | 总览、明细和价格列表使用同一有效价表 |
| 原有手工覆盖 | [价格投影测试](<../../tests/test_pricing.py>) | 同步不覆盖手工价，明确零价仍为零 |
| 网络或数据异常 | [目录解析测试](<../../tests/test_price_catalog.py>)、装配测试 | 返回失败并保留旧目录与手工价 |
| 同名来源存在差价 | 目录解析测试 | 有可信原厂时用原厂；无法消歧时不猜价 |
| 已装0.3.0数据库 | [存储测试](<../../tests/test_event_store.py>) | 升级到 schema 3 后保留明细、手工价与提交证明 |
| 目录有数千模型 | 页面冒烟 | 一页最多渲染50条，搜索不改全局统计筛选 |
| 插件未启用或无补丁 | 页面冒烟 | 显示采集未启用或等待Provider，不把读取成功当成正在采集 |

## 升级与实际环境检查

1. 备份数据后安装完整0.3.1包，重载插件，同时更新后端和页面文件。浏览器强制刷新，静态资源URL带版本参数以避免继续加载旧样式和脚本。
2. 打开价格统计。已有用量应直接显示模型、调用数和Token，无需先创建手工价。
3. 点击更新价格。服务器需要能直接访问固定HTTPS价格源；失败应有提示，不能显示更新成功。
4. 检查自己的原始模型ID是否匹配目录。自定义别名或目录未收录的模型需要手工设价，不会按相似名称自动套价。
5. 在实际AstrBot容器检查顶部高度、表格滚动、明暗主题和编辑状态。确认价格覆盖与自己供应商的单位、倍率和账单规则一致。

当前环境仍缺少 BrowserSkill 的 bsk 程序，未完成0.3.1真实浏览器截图验收，也没有访问用户截图中的远程AstrBot会话。界面结构及数据链路已测试，但不宣称像素级一致；实际视觉验收仍需上述步骤。
