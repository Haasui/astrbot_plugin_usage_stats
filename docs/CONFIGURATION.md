# 配置参考

配置项与默认值来自 [_conf_schema.json](<../_conf_schema.json>)。常用四项可在 **用量统计 → 数据管理** 保存；其余项通过 AstrBot 的插件配置管理。

## 可在页面保存的设置

| 配置项 | 类型 | 默认值 | 用途与范围 |
| --- | --- | --- | --- |
| enabled | bool | false | 开启用量采集；关闭后停止后续采集并还原包装，不删除已有统计 |
| detail_history | bool | false | 保存单次调用时间、结果、用量和耗时；需要总开关同时启用 |
| keep_days | int | 60 | 统计保留窗口；Web 接受 0-3650，0 不按日期清理 |
| detail_max_events | int | 20000 | 已存明细的保留目标，也是待写队列上限；Web 接受 1-200000，两者行为见下方 |

页面使用实际当前值，保存写回原始 AstrBotConfig 对象。异步保存需明确提交成功，之后才更新运行配置。接口的校验、回滚与应用流程见 [main.py](<../main.py#L572-L683>)。

正常保存会应用启停、明细和保留设置。若配置已保存而运行状态未完整应用，页面提示重载。旧草稿或同时提交发生版本冲突时，先还原服务器值后再修改；未保存输入不被自动刷新覆盖。

减少保留范围会影响历史数据，操作前先备份。已写入 SQLite、等待日汇总提交的恢复记录可暂时超过保留目标；尚未落盘的明细队列仍有硬上限，超限时丢弃最旧项并告警。队列裁剪不删除日汇总路径中的对应调用计数，但被丢弃的单次明细不能保证恢复。

## 通过宿主配置的进阶项

修改这些项后，按宿主提示重载插件。

| 配置项 | 类型 | 默认值 | 用途及特殊值 |
| --- | --- | --- | --- |
| memory_cap | int | 20000 | 内存调用数超过目标时尝试保存；成功后清空逐条缓冲。失败保留待保存记录，可暂超目标；0 不以条数触发这项限制 |
| save_every | int | 50 | 每累计这些调用尝试保存日汇总；0 关闭按调用数触发，不关闭其他保存入口 |
| refresh_interval | int | 60 | 定时发现新 provider 类的间隔，单位秒；同一循环批量写明细与日志，0 关闭该循环 |
| call_log | bool | false | 启用独立 calls.log，记录统计与请求构成长度，不写正文；含会话标识 |
| call_log_lines | int | 20000 | 文本日志裁剪目标；磁盘行数超过目标两倍后裁回目标，0 不裁剪。Web 单次读取上限不随之取消 |
| debug | bool | false | 每笔调用在 AstrBot 主日志输出归因、会话标识、输入构成长度与耗时 |

三种记录有不同的写入触发：

- 日汇总：调用数阈值、内存超限、普通 /usage 查询、正常卸载和页内设置应用时尝试保存。
- 结构化明细：日汇总保存前、页面统计/导出查询、定时循环和正常卸载时尝试写入。
- 文本日志：定时循环、日志页读取和正常卸载时批量写入，普通 /usage 不负责刷文本日志。

refresh_interval=0 会关闭该循环的 provider 发现与日志/明细刷新，不关闭其余入口。save_every=0 只关闭按调用数保存日汇总的触发。

## 开关之间的关系

- enabled 控制新调用采集，不控制已有历史是否可读。
- detail_history 只控制结构化明细，不会自动开启 call_log 或 debug。
- call_log 与 debug 均独立启用，都会带来会话标识记录。
- keep_days 同时参与日汇总与明细的滚动清理；call_log_lines 独立控制文本日志。

日志与明细的内容区别、文件位置和备份步骤见[使用指南](<USAGE.md#日汇总明细和文本日志>)。

## 兼容旧配置

[配置读取器](<../main.py#L144-L153>)兼容 advanced 对象中的同名项：存在非空值时会先读取该值，再读取根配置。Web 保存会同步更新已有的同名覆盖，避免页面保存后仍被旧值遮蔽。

Web 校验范围与底层 int 类型不是同一概念。旧配置中超出页面范围的整数可能仍被显示，但提交前需调整到合法范围。不要用字符串 true 或 false 代替 JSON 布尔值。
