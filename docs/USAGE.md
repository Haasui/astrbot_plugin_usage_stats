# 使用指南

## 安装与启用

在 AstrBot 插件管理中使用[项目仓库地址](<https://github.com/Haasui/astrbot_plugin_usage_stats>)安装并加载插件。安装或更新后，按宿主提示重载插件，再打开插件提供的 **用量统计** 页面。页面可能出现在插件入口或扩展功能中，位置由宿主版本决定。

进入 **数据管理**，开启 **启用用量采集** 并保存。插件默认不安装采集包装，只有开启后才开始记录后续调用。发起一次文本模型请求，再刷新总览。

Web 页面依赖宿主的 AstrBotPluginPage Bridge；页内保存还需要 AstrBotConfig 的保存接口。缺少页面能力的宿主，可通过 AstrBot 插件配置启用后使用聊天指令。页面若提示后端未提供设置或保存接口，检查是否完整更新了插件、重载并强制刷新，而不是反复点击保存。

项目的最低版本声明见 [metadata.yaml](<../metadata.yaml>)。Web 设置使用的接口契约可查 [AstrBot 4.29.4 配置实现](<https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/config/astrbot_config.py>)，这不等于所有宿主版本的 Web 能力都相同。

## 在页面保存设置

数据管理页提供四项常用设置：采集总开关、调用明细开关、保留天数、明细数量上限。范围和默认值见[配置参考](<CONFIGURATION.md#可在页面保存的设置>)。

1. 修改需要调整的值，点击 **保存设置**。
2. 看到保存并应用成功后，刷新页面确认值仍保留。
3. 若提示已保存但需要重载，说明宿主配置已提交，运行状态未全部应用；重载插件后再确认。

保存失败时运行配置保持不变，表单保留草稿。若提示设置已变化，先还原服务器值，再决定如何修改。自动刷新不会替你丢弃未保存输入。

关闭采集不会删除已有统计。只开启明细、不打开总开关，也不会擅自启动采集。缩短保留范围或减少明细上限前应备份，需要清理的数据会在统计保存和裁剪时处理。

## 看总览与趋势

总览、分析、明细和价格页的统一筛选支持今天、近 7 天、近 30 天、全部和自定义时间，并可叠加来源插件、模型提供方（provider）、模型与结果。日志和数据管理页不显示这些统计筛选。

自定义起止时间需点击应用后才成为查询条件；编辑草稿不会改变自动刷新或导出的范围。读取失败时保留上次成功结果，并在内容区标明。

- provider 是 AstrBot 中配置的连接标识，不等同于供应商账户或密钥。
- 统计日界固定为 UTC+8；自定义结束时刻不包含在区间内。
- 图例可隐藏某个系列，这只改变图表显示，不改变顶部指标的统计范围。
- 模型较多时，趋势图展示 Top6 和其他系列。

总览数字只覆盖已记录调用。部分调用没有返回 usage 时，Token 合计不是全部真实消耗。成功率、缓存占比、TPS 和平均耗时也有各自的样本范围，完整定义见[统计口径](<ARCHITECTURE.md#统计口径>)。

### 为什么筛选后记录变少了

旧历史只有插件、日期和模型维度的日汇总，不能还原单次调用时间或按单笔结果拆分 Token。按成功、失败、取消或子日时间筛选时，无法精确匹配的旧汇总会排除，页面会显示排除数量。

关闭明细时，日汇总仍可累计；开启明细只影响之后的记录，不回填过去的单次调用。

## 查看请求明细与导出

**请求明细** 展示保存下来的单次调用，可分页、调整列宽和列显隐。选择 **导出 CSV** 后，导出当前筛选条件匹配的明细，不仅是当前页。

单次导出最多 5000 条，超过时会提示截断。旧日汇总不伪装成明细行。CSV 含统计字段，不包含会话标识、消息正文、API 密钥或错误正文。

浏览器和宿主 iframe 需要允许下载。如果已返回数据却没有文件，先检查浏览器下载提示和宿主权限。

## 配置估算价格

价格统计会列出已使用模型的调用数和用量，即使还没有给它设价。有调用时默认查看已用模型，可切换全部目录查询其他参考单价；没有活动的目录项不显示调用成本。

编辑器会说明价格作用范围。编辑已有通用覆盖会影响其他使用该价格的提供方；要保留通用价并新增专属价，使用手动添加并填写提供方标识。

1. 在 **价格统计** 点击 **更新价格**，从 Models.dev 获取公共参考目录。
2. 查看计价覆盖和每行来源。没有匹配价的调用保持未计价，不当作免费。
3. 若使用自定义模型名、转发服务或合同价格，编辑对应行，保存手工覆盖。
4. 需要恢复公共参考价时，删除对应的手工覆盖。

单价使用 **USD / 百万 Token**。留空是未知价格，明确填写 0 才表示该项免费。手工价优先级及估价公式见[费用计算](<ARCHITECTURE.md#费用计算>)。

模型 ID 必须精确匹配记录中的原始模型名。填写 provider 时也要匹配记录中的连接标识；留空表示该模型的通用手工价，不是要求填写 openai 或 anthropic 等厂商名。

公共更新只请求固定的 [Models.dev 地址](<https://models.dev/api.json>)，不发送本地模型列表、用量或凭证，也不使用环境代理设置。服务器需能直接访问该 HTTPS 地址。网络或目录解析失败时保留上次目录，手工覆盖不被同步改写。

估价使用当前价表重算历史，不是保存调用时的账单快照。不包含汇率、税费、服务档位与长上下文倍率；旧日汇总也能估价，不要求开启明细。价格搜索仅筛选本页目录，不改变全局用量条件。

## 聊天指令

以下指令均要求 AstrBot 管理员权限。主指令别名为 /用量 和 /usg。

| 指令 | 用途 |
| --- | --- |
| /usage | 按模型查看全部已保留历史与当前数据 |
| /usage day | 查看今天 |
| /usage week | 查看近 7 天 |
| /usage full | 按插件展开到模型，附失败与输入图片数 |
| /usage status | 查看本次运行的采集和保存诊断 |
| /usage help | 查看指令帮助 |
| /usage_clear | 清除尚未并入已保存日汇总的内存调用及其对应明细 |
| /usage_reset | 清除日汇总、内存统计和结构化明细 |

未识别的参数按全部处理；这些子命令不组合成多级筛选。普通用量查询会尝试保存统计，help 和 status 不走这次保存。采集总开关关闭时，/usage 返回未启用信息；Web 页面仍可读取已有历史。

/usage status 的本次运行记录是启动以来的诊断计数，不是当前筛选范围或剩余历史数量，不能直接与总览相减。full 中的图片数来自文本请求显式 image_urls 参数的数量，不代表图片生成调用数。

## 日汇总、明细和文本日志

三者用途不同：

| 数据 | 用途 | 是否含会话标识 |
| --- | --- | --- |
| 日汇总 | 按插件、日期和模型保留计数与 Token | 不含 |
| 结构化明细 | 单次时间、结果、Token、耗时及价格查询 | 不含 |
| 可选文本日志 | 请求构成长度、历史轮次、工具/图片数量等排障信息 | 含 |

调用明细开关与文本日志开关独立。需要文本日志时，在 AstrBot 插件配置中开启 call_log，然后到 **调用日志** 手动读取或刷新。

日志页默认按时间从新到旧显示。展开记录可查看原文，也可切换到原文视图或按输入 Token 排序。原文视图支持自动换行，只影响显示。单次最多读取最近 5000 行，扫描最多 8 MiB。日志不使用统计筛选，也不随统计自动刷新。导出包含本次读取的原文行，仍按输入 Token 降序排列，可能只覆盖文件尾部。

调用日志和 debug 主日志都可能含会话标识。分享前先脱敏；两种日志都不主动记录消息正文。

## 备份与重置

数据位于宿主插件数据根目录下的 astrbot_plugin_usage_stats 子目录，由 [main.py](<../main.py>)确定位置：

- usage.json：日汇总及明细包含关系的提交标记。
- events.db：结构化明细、手工价格、公共价格缓存和提交证明。
- calls.log：可选文本日志。

正常停止 AstrBot 后，再把 usage.json 与 events.db 一起备份或还原。只还原一份可能造成提交证明不匹配。文本日志按需单独备份；采集配置由宿主配置对象保存，迁移统计文件不能代替迁移插件配置。

| 操作 | 删除 | 保留 |
| --- | --- | --- |
| 关闭采集 | 不删除统计 | 已有日汇总、明细、价格和日志 |
| /usage_clear | 未保存的内存调用、对应明细与待写项 | 已保存历史、价格和文本日志 |
| 页面重置或 /usage_reset | 日汇总、内存统计、全部结构化明细 | 采集配置、手工价、公共价格缓存和文本日志 |

页面重置先展开确认区域，再使用独立的清空按钮确认；直接双击触发按钮不会执行重置，取消或超时也不清理数据。若提示未全部持久化，不要当作磁盘数据已清空，应检查存储后重试。错误归因不会因为修改规则自动重算旧记录。

保存失败时，日汇总内存调用和已写入 SQLite 的恢复记录可暂时超过对应目标。未落盘明细队列仍有硬上限，超限会丢弃最旧明细并告警；对应调用计数仍在日汇总路径中。未提交到任一文件的内存记录，在进程异常退出时可能丢失。发现磁盘空间或权限错误应尽快处理。

## 常见问题

- **统计没有增长**：确认页面显示采集已启用，发起新的文本模型调用。若仍等待采集就绪，展开运行诊断看方法清单，并检查 provider 是否已加载和定时重扫是否关闭。
- **有用量但没有费用**：核对模型 ID、provider、相关输入/输出/缓存单价和计价覆盖。公共目录缺少模型时手工设价。
- **调用都归到主对话**：归因依赖调用栈，无法识别的来源会记录为 main_agent，不会猜测插件。
- **新功能缺失或设置不能保存**：完整更新后端与页面文件，重载并强制刷新。宿主没有配置保存接口时，页面不会只改内存后假报保存成功。
- **证明不匹配或旧实验数据库不能合并**：保留原文件，使用同批次备份核对恢复，不手工删除证明表来强行去重。
